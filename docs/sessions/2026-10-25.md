# Session log - 2026-10-25

(Written up 2026-10-26 to 2026-10-28; the container restarted in between.)

# 0.1.0: one sample to a whole instrument

Asked: a VST3 that makes a whole virtual instrument from a single sample -
every semitone, round robins on every key, dynamic layers from pp to ff that
change the timbre, and articulations made automatically. The repository held
only a GPLv3 licence.

- **The engine** ([0001](../decisions/0001-spectral-resynthesis-not-stretched-copies.md),
  [0002](../decisions/0002-a-zone-is-a-seeded-performance-played-live.md)):
  YIN pitch tracking, STFT partial tracking, a noise residual in 24 bands, an
  oscillator bank and filter bank per voice, zones as seeded variations, nine
  articulations, keyswitches, legato, the sustain pedal, SFZ export. JUCE
  8.0.15 (AGPLv3, which the GPL can carry).
- **The first test run failed 10 of 91 checks**, every one a real fault or a
  test's own:
  - keys above F#5 read 12 to 28 semitones flat - the harmonics had faded
    under the noise because the whole spectrum was tied to absolute
    frequency; separating the source slope (which moves with pitch) from the
    body (which doesn't) fixed it: every key within 4 cents;
  - the resynthesis was 14 dB too loud in the bands under and between the
    first harmonics: the band holding the fundamental was masked entirely and
    fell back to the partial's own energy; now interpolated from its
    neighbours (mean distance 3.5 dB to 0.45 dB);
  - a stretched spectrum's partial 20 was read 0.25 low, because YIN's pitch
    is biased on inharmonic tones; the pitch is now taken from the first
    partial;
  - four brightness checks failed because the test's 0.17 s window was
    shorter than its 8,192-sample FFT (the spectrum came back empty) - the
    test's fault;
  - a 60 ms sample did not loop - correct in Auto (it counts as plucked); the
    test now asks for Loop.
- **A demo phrase peaked at +8 dBFS**: Brightness added about 10 dB of
  energy at ff. Its tilt is now energy-normalised, so loudness is Dynamic
  range's alone, and the source is normalised to -18 dBFS; four-note ff
  chords peak near -2 dBFS. Marcato's accent, which had leaned on that extra
  energy, was made explicit (+7 dB falling to -4).
- pluginval could not be run (the container refuses downloaded binaries);
  `Tests/PluginTests.cpp` was written instead: the real processor and editor,
  state round trip, rebuilds while playing.
- CI (`.github/workflows/build.yml`) builds Windows, macOS (universal) and
  Linux and runs both suites. Its first run was queued when the session moved
  on; nothing here has run on Windows or macOS.

# Later - 0.2.0: the house style and Apple's guidelines

Asked: follow the house style and GUI guidelines from the Good Idea repo.
Good Idea is a ReaImGui script; its rules (`docs/COLOUR.md`, decisions 0030
and 0031, `docs/apple-hig-review.md`, CLAUDE.md's "Words on screen" and HIG
sections) were applied the way Noterator, a JUCE sibling, applies them
(`Source/App/Theme.*`, its 0015 and 0048).
[0003](../decisions/0003-the-house-scheme-and-apples-guidelines.md) and
[0004](../decisions/0004-the-windows-words-follow-apples-writing-guidelines.md).
No change to the sound.

- **The palette**: `Source/Plugin/Theme.*` replaces `LookAndFeel.*`. Teal,
  amber, blue and the blue-to-red layers are gone; the yellow is spent only
  on what is on; layers are greys from `#2A2F37` to `#8F96A2` with their
  names written beside them.
- **Type, sizes, keyboard, message, Undo, Text size**: as 0003 lists. The
  content is laid out for `width / scale` and wraps (`Flow`, panels wrapping
  their own controls, the views' text rows), inside a viewport that scrolls.
- **Words**: as 0004 lists; parameter ids unchanged, so 0.1.0 projects open.
- **The checks** (`PluginTests`) found, before they passed:
  - every knob unreachable from the keyboard - JUCE's `Slider` turns keyboard
    focus off by default;
  - the articulation buttons without tooltips until the first timer tick;
  - the Mapping panel's Seed and New Takes running off the panel at the
    smallest width - panels now wrap their controls;
  - the library's two legend lines drawn over each other at 200% on a narrow
    window (seen in the screenshot, not caught by the first checks); the
    views now lay their text out in `resized()`, wrapping, and the test
    checks every view's text boxes for overlap and overflow;
  - two of the test's own mistakes: a combo box's text checked against the
    ground rather than the grey it sits on, and secondary text checked on the
    menus, where it is never used.
- **One shortfall kept**: the ink on the house's held-button grey `#8F96A2`
  is 6.0:1 - above Apple's 4.5:1 minimum, below the 7:1 target, and shown only
  while a button is pressed. It is the family's value, so it was measured and
  written down (`docs/apple-hig-review.md`), not changed; the test holds it to
  4.5:1.
- **Proving the checks bite** (`bite.py` in the session scratchpad: a copy of
  the tree, one rule broken at a time, the plugin test built and run):

  | Broken on purpose | Result |
  | --- | --- |
  | secondary text `#8A919C` | BIT - text 7:1 |
  | no ink bar on a chosen button | BIT - the ink bar |
  | controls 24 points tall | BIT - shorter than 28 points (at first only through the ink bar check: see below) |
  | controls 4 apart | MISSED, then BIT - closer than 12 points |
  | a click takes the keyboard | BIT |
  | a button in sentence case ("New takes") | BIT - title style |
  | "..." for "…" | BIT |
  | tooltips not broken into lines | BIT - a line over 64 characters |
  | a tooltip that is not a sentence | BIT |
  | labels at 11 points | BIT - under 13 points |
  | panels that don't wrap | BIT - runs off its panel |
  | the focus ring in the yellow | BIT |
  | no Undo after New Takes | BIT |
  | text drawn over text in a view | BIT |
  | Text size not applied | BIT - 200% scales the window |

  The miss was a dead check: the size and gap checks compared against the
  theme's own `controlHeight` and `gap`, so breaking the constant moved the
  check with it. They now hold Apple's 28 and 12 themselves.
- **The macOS CI job hung for six hours** (cancelled by GitHub) in the
  0.1.0 plugin test, after the engine tests passed in 3.5 s; Windows and
  Linux passed both. The test ran its own message loop, and on the Mac
  `JUCEApplicationBase::main` is what sets up NSApplication
  (`initialiseNSApplication`), which that loop never did. The test is now a
  `JUCEApplicationBase` started through `JUCEApplicationBase::main`, prints
  unbuffered, and has a five-minute watchdog; CI has step and job timeouts.
  CI run 2 (2026-10-28): Windows, macOS and Linux all build and pass both
  suites; the Mac's tests take 7 seconds.
- Docs in the house shape: `CLAUDE.md`, `docs/decisions/`, `docs/sessions/`,
  `docs/COLOUR.md` (copied from Good Idea, kept by hand),
  `docs/apple-hig-review.md`, `docs/HANDOVER.md`; the README rewritten in a
  musician's words.

Left open: Increase Contrast and Reduce Motion not read from the system;
VoiceOver reads the controls' names but not the views; no real recording has
been heard, only synthetic tones measured; Windows and macOS only built and tested by CI, never played in a host.
